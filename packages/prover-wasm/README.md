# `@beatex/prover-wasm`

Browser companion to `@beatex/sdk`. It implements `BeatExProver` with one
long-lived module worker and one WASM runtime. Only the four trader proving keys
are fetched, and each is loaded on first use:

| Key | SDK methods |
| --- | --- |
| `balance` | `proveDeposit`, `proveWithdrawal` |
| `order` | `proveOrder`, the order half of replacement/rollover |
| `release` | `proveCancellation`, the release half of replacement |
| `settlement` | `proveSettlement`, the settlement half of rollover |

Aggregator folding and aggregate-publication provers are intentionally not in
this package.

## Usage

```ts
import { CacheStorageAssetCache, createWasmBeatExProver } from "@beatex/prover-wasm";
import manifest from "./beatex-prover-manifest.json" with { type: "json" };

const prover = createWasmBeatExProver({
  manifest,
  assetBaseUrl: new URL("/beatex-prover-assets/", location.href),
  assetCache: new CacheStorageAssetCache(),
});

const client = createBeatExClient({ rpc, signer, storage, prover, /* ... */ });
```

Call `prover.dispose()` when the application no longer needs it. The default
worker is resolved as `./worker.js` from the installed package. A bundler that
emits workers separately can supply `workerUrl`.

## Building Devnet assets

Install the version-matched `wasm-bindgen-cli` once, then generate the runtime,
four proving keys, and manifest into a new directory:

```sh
cargo install wasm-bindgen-cli --version 0.2.100 --locked
npm run build:runtime -- /path/to/new/beatex-prover-assets
```

Host that output directory as immutable static files and pass its
`manifest.json` to `createWasmBeatExProver`. The current exporter produces the
same deterministic Devnet parameters as the verification-key accounts created
by `devnetSetup.sh`. A production deployment must replace those parameters and
the corresponding onchain verification keys with ceremony-generated assets.

## Manifest and integrity

Assets are never used until both their declared byte length and SHA-256 digest
match. Digests are lowercase hexadecimal SHA-256 strings.

```json
{
  "schemaVersion": 1,
  "backend": "beatex-arkworks-groth16-wasm-v1",
  "provingKeyEncoding": "arkworks-canonical-uncompressed-v1",
  "runtime": {
    "url": "beatex_trader_prover.wasm",
    "byteLength": 1234567,
    "sha256": "<64 lowercase hex characters>"
  },
  "circuits": {
    "balance": { "circuitVersion": 1, "provingKey": { "url": "balance.pk", "byteLength": 1, "sha256": "<digest>" } },
    "order": { "circuitVersion": 1, "provingKey": { "url": "order.pk", "byteLength": 1, "sha256": "<digest>" } },
    "release": { "circuitVersion": 1, "provingKey": { "url": "release.pk", "byteLength": 1, "sha256": "<digest>" } },
    "settlement": { "circuitVersion": 1, "provingKey": { "url": "settlement.pk", "byteLength": 1, "sha256": "<digest>" } }
  }
}
```

`CacheStorageAssetCache` is opt-in because applications have different storage
and eviction policies. `ProverAssetCache` and `ProverAssetTransport` are small
interfaces for IndexedDB, service-worker, authenticated CDN, and test adapters.
Cached bytes are reverified before use; the content digest is also part of the
cache key, so a deployment can safely replace an asset URL.

The digest check is also a security boundary: after it succeeds, the WASM
runtime skips redundant per-point curve validation while decoding the large
uncompressed key. Applications must load keys through `WasmBeatExProver`, or
perform the same authentication before calling the low-level WASM API.

## Runtime ABI

The package ships the small JavaScript glue generated by `wasm-bindgen`. The
worker initializes that glue with the separately hosted, integrity-checked
WASM bytes and creates one `TraderProver`. Requests cross the boundary as
native structured values, so `bigint` and `Uint8Array` are never converted
through JSON or JavaScript `number`.

`TraderProver` loads balance, order, release, and settlement keys lazily. The
WASM runtime does not expose trusted setup or generate proving parameters.

The order prover must return ciphertexts in canonical wire order:
`buy[0], sell[0], buy[1], sell[1], ...`. The TypeScript bridge deliberately
passes that array through unchanged.

Proof cancellation is cooperative at worker message boundaries. A synchronous
WASM proof already executing cannot be preempted without terminating the shared
worker, but an aborted request is rejected and its late result is ignored.

The committed integration test runs all four leaf circuits in real
single-threaded WebAssembly. Set `BEATEX_PROVER_ASSETS` to a generated asset
directory and run `npm run test:wasm`.

On the development Apple M4 under Node's single-threaded WebAssembly runtime,
the current checkpoint measures approximately 1.87 seconds for deposit, 1.95
seconds for public withdrawal, 15.21 seconds for a 17-level order, 2.32 seconds
for release, and 2.63 seconds for settlement. Replacement and rollover take
16.00 and 16.29 seconds. The 9.8 MiB,
83.8 MiB, 10.4 MiB, and 11.3 MiB uncompressed keys decode in about 22 ms, 174
ms, 22 ms, and 22 ms after integrity verification. Final browser latency and
peak-memory measurements remain a frontend integration gate.
